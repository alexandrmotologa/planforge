# PlanForge Architecture

PlanForge runs as a single self-contained binary under 30MB of RAM. It processes query execution plans locally without transmitting schema details, table names, row counts, or filter parameters over the network.

## Pipeline overview

The analysis workflow consists of four sequential stages:

1. **Ingestion and normalization**: Accepts PostgreSQL JSON, psql tree text, MySQL JSON, and MySQL EXPLAIN ANALYZE formats. The parser extracts cost values, loop counts, operator names, row counts, buffer cache statistics, and filter predicates into a unified node tree.
2. **Diagnostic intelligence**: Evaluates node durations to identify time hogs consuming over 50% of runtime. Calculates the ratio between planner row estimates and actual rows returned to flag outdated statistics. Calculates buffer cache hit ratios and total megabytes read from storage.
3. **Missing index synthesis**: Inspects unindexed table scans with filter predicates. Classifies columns into equality and range categories, cross references sort keys from parent operators, and outputs concrete DDL statements (`CREATE INDEX CONCURRENTLY` for PostgreSQL and standard index DDL for MySQL).
4. **Presentation and delivery**: Serves the embedded React 19 interface via the standard Go HTTP server, prints text summaries in terminal environments, or generates standalone single-file HTML reports.

## Component breakdown

### Parser package (`internal/parser`)
- `models.go`: Unified structures for plan nodes, buffer statistics, timing breakdowns, and worker details.
- `postgres_json.go`: Decodes nested PostgreSQL JSON trees. Calculates exclusive operator durations by subtracting child subtree timings from parent node loops.
- `postgres_text.go`: Parses text dumps generated by psql using indentation depth and prefix markers.
- `mysql_json.go`: Extracts operations from MySQL `query_block` structures including nested loop joins, temporary filesorts, and table access modes.
- `detector.go`: Auto detects dialect and input format using JSON keys and token heuristics.

### Diagnostic engine (`internal/analyzer`)
- `bottlenecks.go`: Finds operators whose exclusive execution time exceeds 20% (warning) or 50% (critical) of total query duration.
- `estimation.go`: Detects catalog misestimates where the ratio between actual and estimated row count exceeds 10x.
- `buffers.go`: Measures shared buffer hits against disk block reads, translating block counts into physical read megabytes.
- `memory_spills.go`: Flags operators writing to temporary files on disk due to memory constraints (`work_mem`).
- `jit.go`: Evaluates Just-In-Time compilation overhead, alerting when JIT compilation exceeds query execution time.
- `antipatterns.go`: Identifies SQL anti-patterns including correlated SubPlan loops, implicit typecasts, and lossy bitmap rechecks.
- `analyzer.go`: Combines individual findings into an aggregate health score (0 to 100) and letter grade (A through F).

### Index advisor (`internal/advisor`)
- `indexer.go`: Extracts column names and functional expressions (`lower(email)`) from filter expressions. Places equality predicates (`col = val`, `col IS NULL`) at the start of composite index definitions, appends range predicates (`col > val`, `BETWEEN`), and adds order keys from subsequent sort nodes. Generates HypoPG hypothetical index statements for cost simulation without physical storage allocation.

### Live runner (`internal/runner`)
- `runner.go`: Connects directly to PostgreSQL or MySQL databases using native drivers, executing `EXPLAIN (ANALYZE, BUFFERS)` in safe rolled-back transactions.

### Schema anonymizer (`internal/anonymizer`)
- `sanitizer.go`: Replaces table names (`tbl_1`), column names (`col_1`), and literal filter values (`'***'`) with generic tokens while preserving plan structure and execution metrics for secure external sharing.

### Embedded web studio (`web/`)
Built with React 19, TypeScript, and Tailwind CSS. The compiled bundle is embedded into the Go binary using `//go:embed`, allowing deployment without Node.js or external static file dependencies.
